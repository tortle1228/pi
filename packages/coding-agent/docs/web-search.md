# Web Search

The built-in `web-search` extension adds a `web_search({ query: string })` tool. It supports `zai`, `openai`, `anthropic`, and `xai`, and experimentally `openai-codex`. On `xai` it also adds `x_search({ query: string })`, which searches posts on X. If `PARALLEL_API_KEY` is set, it also adds `web_fetch` and `web_research`, and `web_search` works for every provider: a provider without native search uses Parallel, and a native search that fails is retried once with Parallel. To turn the extension off, add `-builtin:web-search` to `extensions` in [settings](settings.md#resources).

Select a Z.AI, OpenAI, Anthropic, or xAI model and ask pi to search, for example: `Search the latest TypeScript release notes and cite the sources.` On xAI, ask for posts on X to use `x_search`. With `PARALLEL_API_KEY` set, the same request works on any other provider.

Native tools reuse the selected provider's credentials and have no separate credential file. Z.AI requires a compatible Coding Plan subscription; OpenAI, Anthropic, and xAI API searches use API billing. `openai-codex` uses the existing ChatGPT/Codex login and may consume subscription usage. An Anthropic or xAI subscription login is experimental and may consume subscription usage or be rejected. Parallel uses `PARALLEL_API_KEY` only; pi does not store a Parallel login.

## Availability

`web_search` enables on session start, model selection, and `/tree` when the selected provider has a native search, or when `PARALLEL_API_KEY` is set, and disables otherwise. `x_search` enables only for `xai`. `web_fetch` and `web_research` enable only when `PARALLEL_API_KEY` is set. Other tools keep their active states. Manually disabling one lasts until the next of those events. Without credentials, a visible tool reports an authentication error when called.

Naming a tool does not enable it when its backend is unavailable: `"defaultTools": ["+web_search"]` and `--tools read,web_search` have no effect on a provider without native search unless `PARALLEL_API_KEY` is set, `+web_fetch` and `+web_research` have no effect without that key, and `+x_search` has no effect except on `xai`. To keep one off, use `"defaultTools": ["-web_search"]`, `["-web_fetch"]`, `["-web_research"]`, or `["-x_search"]`. `-builtin:web-search` does not load the extension at all. `--tools` also restricts them: `--tools read` leaves them off on every provider.

The provider and the Parallel key are checked again when a call starts. Without a native backend and without a Parallel key, the call errors instead of using another service. A native failure falls back to Parallel only when the key is set and the caller has not cancelled. A search already in flight continues with the provider and credentials captured when it started. A native search can be billed before it fails, so a fallback can be charged twice.

## Backends

**Z.AI.** Each search resolves credentials at call time and opens its own connection to the official [Web Search MCP](https://docs.z.ai/devpack/mcp/search-mcp-server). It discovers `webSearchPrime` (also accepting `web_search_prime`), checks that the remote schema accepts `{ search_query: query }`, and returns readable content with source links intact. Structured-only results are serialized as JSON. The original MCP tools are not exposed separately. Searches consume Coding Plan allowance. The endpoint is fixed, so if the `zai` provider's `baseUrl` points at another host, such as a proxy, searches fail with an error instead of sending that key to Z.AI. If `PARALLEL_API_KEY` is set, that error is retried once with Parallel.

**OpenAI.** The search uses pi's Responses transports and the selected model to request OpenAI's built-in web search, and returns the answer and source URLs. Models without web search support return an error. If `PARALLEL_API_KEY` is set, that error is retried once with Parallel; otherwise there is no automatic model or provider fallback. Codex support is experimental: the subscription backend may reject this request. Searches are independent requests that send only the query, not the conversation. OpenAI API searches incur model and search charges.

**xAI.** `web_search` and `x_search` use pi's Responses transport and the selected model to request xAI's server-side `web_search` or `x_search` tool, and return the answer and source URLs. Models that do not support the tool return an error. A failed `web_search` is retried once with Parallel when `PARALLEL_API_KEY` is set; `x_search` has no fallback. Searches are independent requests that send only the query, not the conversation. API searches incur model and search charges. Subscription (OAuth) login follows the provider's existing auth and is experimental.

**Anthropic.** The search uses pi's Messages transport and the selected model to request Anthropic's server-side `web_search_20260209` tool (dynamic filtering), and returns the answer and source URLs. Models that do not support this tool return an error. If `PARALLEL_API_KEY` is set, that error is retried once with Parallel; otherwise there is no automatic model or provider fallback. Searches are independent requests that send only the query, not the conversation. API searches incur model and search charges. Subscription (OAuth) login is experimental: it may consume subscription usage or be rejected.

**Parallel.** Set `PARALLEL_API_KEY` from [platform.parallel.ai](https://platform.parallel.ai). `web_search` calls `POST /v1/search` with `mode: "fast"` and the query as both the objective and the only keyword query. `web_fetch({ urls, objective? })` calls `POST /v1/extract` for up to 20 http(s) URLs and returns excerpts, or an error line for each URL that failed. `web_research({ query, effort?, previous_response_id? })` calls `POST /v1/responses` with `model: "parallel"`. `effort` is `low`, `medium`, or `high` and defaults to `medium`. The result is the answer, source URLs, and `Response ID`. A follow-up passes that id as `previous_response_id`; this does not work when the organization has Zero Data Retention enabled. The research question is sent alone, so it must stand on its own. Auth is the `x-api-key` header. Parallel calls are not retried.

Native searches and Parallel search and fetch use a 60-second deadline. Parallel research uses 120 seconds. All of them support cancellation and do not automatically retry billable calls. Errors surface as tool errors. Results over 50KB or 2000 lines are truncated, and the result says so.
